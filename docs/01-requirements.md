# 情侣共享空间 · 详细需求设计

- 版本：v1.0（基线）
- 定稿日期：2026-10-01（讨论确认）
- 状态：已定稿，作为开发与后续会话的需求基准

## 1. 产品定位

一款情侣专用的共享空间手机 App，产品形态是**重笔记、轻日历**：两个人共同
记录、共同查看双方的笔记/记录，正文是主体，时间只是可选属性；绑定时间的记录
会出现在日历中，但产品不做成纯日历待办。数据不依赖服务器，两台设备直接
点对点同步；一方离线也能查看与编辑。

## 2. 目标用户与设备

- 恰好两名成员（情侣），地位完全平等，无主从之分。
- 已知真实场景：**一方 Android、一方 iPhone**，因此必须双平台。
- 每台设备都持有完整数据副本，离线可读可写。

## 3. 功能范围

### 3.1 v1 范围（本期必须做）

- 笔记（记录）增删改查（可离线编辑，重连后自动合并）。
- 笔记列表为主视图（卡片/时间线），日历为辅助视图（月视图）。
- 配图：一条笔记可配多张图片，不限制单张大小。
- 本地提醒（无服务器推送，见 §7）。
- 首次配对（配对码 / 二维码 + 端到端加密）。
- 三种连接方式同步：同 WiFi 自动、蓝牙手动、热点手动。
- 冲突处理：字段级 LWW + 删除墓碑。
- 文件备份：手动导出 / 导入。

### 3.2 明确不做（v1 及近期）

- 待办清单、打卡、纪念日、聊天/留言。
- 服务器、账号体系、云同步、消息推送服务。
- 多人群组（只有两个人）。

### 3.3 预留（字段可预留，界面逻辑以后做）

- 重复事件规则（repeatRule，仅对绑定时间的笔记有意义）。

## 4. 笔记数据模型（用户可见字段）

> 设计理念：**重笔记、轻日历**。不绑定时间的笔记是正常存在，只出现在笔记列表；
> 绑定时间后同时出现在日历。提醒仅对有绑定时间的笔记提供。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 正文 | 多行文本/富文本 | 是（至少非空） | 笔记的主体，列表以正文预览展示 |
| 标题 | 文本 | 否 | 缺省可由正文首行/日期生成 |
| 时间绑定 | 枚举 + 日期时间 | 否 | none（不绑定）/ 全天（仅日期）/ 时间段（起止） |
| 分类/颜色 | 枚举/颜色 | 否 | 列表与日历中区分显示，简约配色 |
| 地点 | 文本 | 否 | 纯文本，不做地图联动 |
| 提醒 | 偏移或具体时间 | 否 | 仅对有绑定时间的记录提供；支持提前 N 分钟或自定义，可关闭 |
| 配图 | 图片集合 | 否 | 多张，不限制单张大小 |
| 重复规则 | 字符串(预留) | 否 | v1 不提供界面逻辑 |

## 5. 视图与交互

> 主入口是笔记列表（像两个人的共享手账/日记），日历只是“看看哪天有安排”的
> 辅助视图。

### 5.1 笔记列表（主视图）

- 默认首页：笔记卡片/时间线，按时间倒序（创建/更新时间或绑定时间）排列。
- 卡片以正文预览为主体，标题可有可无；有图显示缩略图，绑定时间显示时间角标。
- 支持筛选：全部 / 有日期（v1 至少提供这两项）。
- 不绑定时间的笔记同样正常显示，不视为“未完成事项”。
- 空状态文案可爱、亲切（符合简约可爱风格）。

### 5.2 日历视图（辅助视图）

- 月网格；只有绑定了时间的笔记出现在日历，按日期显示柔和标记或微型卡片。
- 点击某一天进入当天笔记列表（复用列表视图，过滤出当天记录）。
- 左右滑动切换月份；今天高亮。
- 无时间绑定的记录不进入日历，避免日历被无日期内容污染。

### 5.3 编辑笔记

- 新建/编辑以正文输入为主（默认聚焦正文）；时间、分类、提醒等是可选区块。
- 时间绑定三种：不绑定 / 全天（选日期）/ 时间段（起止时间）。
- 提醒设置只对有绑定时间的记录展示。
- 配图：从系统相册多选或拍照；缩略图网格展示；可移除。
- 保存后：本地立即生效；若已连接对方则即时推送增量同步。

### 5.4 删除

- 删除需确认；删除后本地立即移除，对方经同步后移除（墓碑保证不复活）。

## 6. 同步需求

### 6.1 连接方式

| 方式 | 触发规则 | 说明 |
| --- | --- | --- |
| 同 WiFi | 自动 | 应用内自动 mDNS 发现已配对设备并自动连接 |
| 热点 | 手动点击 | 一方开热点、另一方连接后，复用局域网发现+TCP 通道 |
| 蓝牙 | 手动点击 | BLE 通道；适合小数据，大图不推荐走蓝牙 |
| 手动兜底 | 手动 | 输入 IP/配对码直连，用于网络隔离等异常场景 |

- “自动连接”只对已配对设备生效，陌生设备不自动连接。
- 连接成功后立即双向增量同步；在线期间编辑后尽量即时同步。
- 离线期间的编辑全部落本地，重连后合并。

### 6.2 冲突规则（核心）

- **字段级 LWW**：每个可编辑字段独立携带“最后写入（时间戳, 设备ID）”，
  比较时**时间戳大者胜，相等则设备ID 大者胜**。
- 示例：A 改了标题，B 改了时间，两者都保留；同一字段同时改，较新者生效。
- **删除 = 墓碑**：删除视为对 deleted 字段的一次写入，同样按 LWW。
  - 一方删除、另一方在删除时间之后又编辑 → 编辑赢，笔记保留。
  - 一方删除、另一方没有更新 → 删除赢，双端都删。
  - 墓碑保留一段确认期（建议 30 天）后压缩清理，防止旧副本把已删记录带回。
- **图片按图片ID 独立 LWW**：添加/移除某张图片是独立操作，不做整图集覆盖，
  避免一方删图后被对方的旧图集“复活”。

### 6.3 配图同步

- 不限制单张大小、不限制总大小（v1）。
- 本地自动生成缩略图用于列表/日历展示；原图完整保留。
- 传输采用分块 + 断点续传 + 自动重试；同步队列持久化，重启不丢失。
- 图片与笔记独立同步，图片未传完时笔记本身先可用（缩略图/占位）。

### 6.4 安全

- 首次配对：扫描二维码或输入配对码，建立信任并交换身份公钥。
- 传输加密：端到端加密（X25519 + ChaCha20-Poly1305）。
- 连接握手校验对方身份，仅与已配对设备通信。

## 7. 提醒需求

- 双方都可为**绑定了时间**的笔记设置提醒（提前 N 分钟或自定义时间，可关闭）；
  未绑定时间的笔记不支持提醒。
- 每台设备在自己本地排定系统通知（无服务器，因此无推送）。
- **已知限制**：对方设备上的提醒，必须等双方完成同步后才能在其本地排定；
  若长期离线，提醒可能错过或延后。
- 需处理通知权限：Android 13+ 通知权限、iOS 本地通知授权。
- 点击通知跳转到对应笔记详情。

## 8. 备份需求

- **导出**：把笔记数据（含同步元数据）与全部图片打包成单个文件
  （zip：JSON + 图片），通过系统分享/文件保存到相册或文件管理器。
- **导入**：选择备份文件恢复。建议**按 LWW 合并**而非整包覆盖，
  以“最新操作”为准，避免误覆盖。
- 图片按内容哈希去重，避免重复存储。

## 9. 非功能需求

- 性能：列表与日历流畅；图片列表用缩略图；本地查询毫秒级。
- 可用性：任何一方断网不丢数据；最终一致（连接后收敛）。
- 电池与后台：iOS 后台同步受限（详见技术设计 §6）；不做常驻后台服务。
- 数据安全：传输加密；本地数据库加密列为 v1 后可选项。
- 语言：界面文案中文，风格简约可爱（圆角、柔和色、轻量插画元素）。

## 10. 验收标准（摘要）

1. Android 与 iPhone 各一台，同 WiFi：App 在前台时能自动发现并自动同步已配对设备。
2. 一方离线编辑多条，重连后双方数据一致。
3. 同一字段双方同时修改：时间较新者生效；不同字段各自保留。
4. 一方删除笔记，另一方同步后不再看到，且不被旧备份/旧副本复活。
5. 大图（如几十 MB）可完整同步、双端可打开；中断后可续传。
6. 提醒按设定时间在本地触发，点击可进入详情。
7. 导出备份文件 → 清空数据 → 导入，可恢复全部笔记与图片。
8. 蓝牙、热点路径在真机上可手动连接并完成小数据同步。
